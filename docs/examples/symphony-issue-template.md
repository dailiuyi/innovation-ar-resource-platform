# Issue 正文模板

由需求准备 Agent 填写并删去占位说明。不要原样入队；外置程序计划另参考 [JSON 示例](symphony-task-plan.json)。

## 已确认需求

- 原始口头需求：忠实转述，区分用户原话和 Agent 建议。
- 目标用户、当前入口与痛点：待填。
- 修改后可观察的行为：待填。
- 验收条件：给出输入、操作、预期结果；UI 写明目标页面、关键按钮和视口。
- 未解决问题：待填；影响实现或验收的关键问题未解决时不入队。

## 范围

- 可修改的文件/模块：与外置计划 allowedPaths 一致。
- 明确保留的行为及不做的事项：待填。
- 必要背景：链接当前业务文档、调用入口；不用历史候选设计代替已确认需求。

## 检查与人工验收

- 容器 profile：quick 或 frontend；后者已包含 quick。
- Java 模块：按实际填写；没有 Java 修改填无。
- 宿主 hostSuites：smoke / scene-ui / accounts / ingestion 中适用项。
- 专项覆盖哪些验收条件，哪些只由人工确认：待填。
- 合成数据需求和准备方式：待填。当前基础种子只含账号、长短名称场景、合成小文件清单版本（无描述，不可渲染），额外功能数据须先补齐。
- 是否存在尚无检查器或环境未就绪的项目：有则先解决，不标 ready。

## 执行与交付

- 模型/深度及选择理由：待填；实际参数由 routing 标签控制。
- 交付：草稿 PR、当前源码证据、宿主待验收项；不合并、不部署。
- 代码失败只允许一次修复复验；再次失败或环境/权限阻塞停止。由控制器检查、按字节发布并持久化状态，编码模型不自行安装/检查/上传。

创建者在本机交接记录中保留外置计划路径、用户的执行授权和入队状态。公开 Issue 不放密码、本机凭据内容、内部数据或完整运行日志。
